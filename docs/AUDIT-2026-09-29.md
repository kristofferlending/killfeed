# KillFeed – audit, 29.09.2026

Two independent passes over the app: one on the clipping logic (`killclip.py`, `kf_core.py`), one on the
GUI and the experience (`killfeed_app.py`). Roughly 50 findings. The four that could destroy data or lose
work are already fixed and shipped — they are listed first so the reasoning survives. Everything below
that is open, ranked by how much it actually costs.

Version audited: 0.3.1-alpha, commit `2e6fc7a`. Fixes landed in `1a7e068`.

## Fixed already

**A broken Tesseract would have deleted the whole recording library.** `ocr()` returned `r.stdout or ""`
and ignored the exit code. A Tesseract that starts but cannot work — tessdata moved by a Windows update,
corrupt `eng.traineddata`, a locked temp dir — exits non-zero with empty output. Every frame then reads as
empty, every recording looks like a quiet session, the ledger records `{"clips": 0}` with no `error` key,
and `delete_clipped_sources` deletes it. With deletion on, one broken install would have walked the whole
library and produced nothing. `ocr()` now raises on a non-zero exit, and the cleanup additionally requires
`hits > 0` on that specific file. A genuinely uneventful recording is kept — the cheap mistake.

**The ledger was keyed by file name.** OBS and Aitum Vertical share a naming scheme, so the same name
routinely exists in both the full-format and the vertical folder. Keyed by name they collapsed into one
entry: the second was silently never clipped, and the cleanup looked up the first one's entry and deleted
a recording it had never processed — the 9:16 backtrack, which is the whole reason `prefer_vertical`
exists. Keys are full paths now; old name-keyed entries still count as "processed" but may no longer
authorise a delete.

**`delete_outputs` with an unset output folder** resolved to the relative paths `Publish\`, `Other\`,
`Recaps\`, `RecapBank\` — next to the process working directory. Now refuses.

**Rescan killed the running file before asking.** Pressing Cancel still cost you the half hour of work on
the current recording. It asks first now. (`reset_all` always did this correctly.)

Two smaller ones went in at the same time: `-map 0:a:0` is now optional, so a recording made with audio
capture switched off is no longer reported as a damaged file; and three status lines stopped printing the
literal words `ok` and `warn` to the user.

## Open — worth fixing before the next release

**Turning on "delete the recording" is retroactive, with no confirmation.** The function iterates every
file in the input folders and deletes any with a clean entry, regardless of age. Someone who has run the
alpha for three months and ticks the box to free space loses everything older than `lookback_days` in one
pass. Suggested: only delete recordings processed after the setting was enabled, and show a one-time
confirmation with the file count and total GB.

**`reset_ledger` can orphan the recap bank permanently.** It strips the `bank` list from every report so
the bank is re-cut — but if the sources were already deleted, `bank_segments` bails at the missing file,
the list is gone for good, and the bank mp4s sit in `RecapBank\` referenced by nothing. Same effect when a
source is re-processed: `process_source` moves the new report over the old one and discards its bank list.
Fix: keep bank entries whose files still exist, and merge rather than clobber on the report move.

**Ledger races can kill a run mid-batch.** `jsave` serialises the ledger with no lock while three threads
touch it: the worker inserting clips, the HTTP thread writing ratings, and the GUI thread iterating
`L["clips"]` for the list. Marking a clip in the browser while a run is placing clips can raise
`dictionary changed size during iteration` inside `save_ledger`; nothing catches it, so the run dies and
the just-clipped sources are never recorded. One `RLock` around every read and serialise closes it.

**`enrich_from_reports` can attribute a stranger's kill to your clip.** The design rule is that the
left-hand kill feed lists everyone and is never proof — which is why `_run` only keeps a feed row when a
banner fired within 2.5 s in the same recording. This function drops that guard and matches any feed row
from any report within `dedup_seconds`. A teammate's 600 m kill four seconds after yours can retitle your
short and push it up the queue. This is the same class of bug as the one that produced the bad upload in
0.3.1. Tighten to the 2.5 s used elsewhere.

**`cleanup` marks clips as tidied even when the delete failed.** `status = "ryddet"` is set
unconditionally after `os.remove` attempts that swallow `OSError`. A file locked by a player or OneDrive
survives on disk but leaves the ledger, so it disappears from dedup and the same kill can be re-clipped as
new. Only set the status when the removal actually succeeded.

**Hiding to tray when the tray icon failed loses the app.** `_start_tray` catches the failure and writes a
log line, but the "Hide to tray" button still calls `withdraw()`. With no icon and no window there is no
way back, and `single_instance()` makes relaunching return silently. Task Manager is the only recovery.
Hide the button when `self.icon is None`.

**Relaunching while it runs in the tray does nothing.** The second instance exits with no message. On
Windows 11 the icon hides under the `^` overflow by default, so "I'll just open it again" is the likely
user action and produces zero feedback. At minimum, show a message box saying where the icon is.

**Changing any timing value auto-opens a dialog whose gold default button deletes everything.** Nudging
"Seconds before the kill" from 8 to 9 and pressing Save pops the Rescan dialog, where `choose()` styles
the first option as primary — and that option is "Start fresh", which empties Publish, Other, Recaps and
RecapBank. "Reset to defaults" chains straight into the same dialog. Reorder so the safe option is first,
or replace the dialog with a dismissible banner.

**Spinbox input is silently discarded, and on the Settings tab it breaks Save entirely.** The Advanced tab
wraps `int(v.get())` in a bare `except: pass`, so typing `eight` gives you "Saved 21:14" with the value
unchanged. On the Settings tab it is unguarded, so a non-numeric recap length raises `TclError` inside the
callback — in a windowed build that traceback goes nowhere and Save appears to do nothing, with settings
half-mutated in memory. Add numeric validation. There is also no cross-field check that maximum short
length exceeds minimum.

## Open — smaller, but real

- `_money()` regexes `\+\$([\d,]+)` against the event kinds, which are always one of four normalised
  words. The condition can never be true; every montage candidate carries `money: 0`. Dead code that
  looks live.
- `build_montage` uses `break` where it should `continue`, so one candidate longer than the maximum
  permanently stalls the recap — and the empty case logs nothing.
- The combination `recap_bank: False` + `keep_source_for_recap: False` + recaps on deletes every source
  immediately and then logs "Recap: no qualifying clips yet" forever. Settings should reject it.
- Pointing `output_dir` at `input_dir` prunes the entire tree in `source_files`, so the app finds zero
  recordings forever with no message. Preflight should catch it.
- `killclip._find()` calls `sys.exit()` at import time when ffmpeg is missing, so the app dies before
  preflight's friendly message can be shown.
- `promote_fallback` reads statuses from a stale batch list and can pick a clip whose file was already
  deleted as a duplicate — the exception is swallowed and the session gets no fallback at all.
- A stopped or paused run still reports "Done." with counts, giving no hint that 26 of 40 recordings were
  never touched.
- "Nothing new" after a session is the most likely moment for a new user to conclude the app is broken.
  It should say what it is waiting for and for how long.
- `montage_now` runs `montage_ready` on the UI thread, which can shell out to ffprobe once per report —
  the window goes Not Responding. And the Stop button during a recap build does nothing, because
  `_concat` never checks a stop flag.
- Raw exception text reaches the user in four places, including `[WinError 5] Access is denied` on the
  last page of the wizard with no suggestion to pick a different folder.
- "No clips with a file on disk yet" is shown as an error dialog to a brand-new user who pressed Browse
  clips before their first run.
- `clips.html` bakes in a port chosen fresh on every launch, so a previously built page always reports it
  cannot save. The page written at the end of an automatic run has no port at all, because the server only
  starts when Browse clips is pressed.
- The clip list rebuilds from scratch every 5 s during a run, destroying selection and scroll position.
- Saving settings mid-run mutates the dict the worker thread is reading, so the rest of the batch is
  clipped with a mix of old and new values.
- `set_autostart` runs PowerShell synchronously on the UI thread with a 20 s timeout, so every Save can
  stall the window, and a failure leaves the checkbox ticked while autostart is not set up.
- No dirty tracking on the settings tabs — switching tabs discards edits with no warning.
- Custom dialogs bind neither Enter nor Escape, and no button is `default="active"`.
- DPI awareness is system-level, not per-monitor v2, and every geometry constant is raw pixels. At 175 %+
  the wizard's nav row can land below the bottom of the screen with no way to resize or scroll — the
  wizard becomes uncompletable.
- `json.dumps` output is injected straight into a `<script>` block in `clips.html`. Not currently
  exploitable since the data is machine-generated, but a filename containing `</script>` breaks the page.

## Wording

"Other" reads as a leftover from the Norwegian `andre` — "Not for publishing" says more. "Shorts today"
counts only Publish, though clips in Other are shorts too. "Recordings scanned" includes failures.
Several tooltips read as changelog rather than help: lead with what the number does, not the study that
chose the default. And two strings tell a gamer to edit JSON or mention `dev-run.cmd`.

## What is genuinely good — don't lose it in a refactor

`preflight()` is the model for error copy in this app: every problem names the fix. "Why is it in this
folder?" states the rule, the numbers and the verdict in three lines. `process_source`'s exception triage
turns ffmpeg and Tesseract failures into plain-language hints instead of tracebacks. The first-hide tray
toast fires exactly once. The thumbnail cache is mtime-aware, so re-cut clips don't show stale stills.
The `-ss`/`-t`-before-`-i` ordering is correct in every branch including the watermark path. `jsave` is
atomic per write. `cluster`/`split` terminates in all branches. The abort path correctly leaves an
interrupted file unrecorded so it is re-clipped next run. And the local rating server is properly scoped:
loopback only, OS-chosen port, two routes, a 4 KiB body cap, 404 on everything else.

The architecture is sound. The gap is between what the code knows and what it tells the user.

## Suggested order

1. Confirmation and an age limit before retroactive deletion.
2. The ledger lock.
3. `reset_ledger` orphaning the bank.
4. The tray trap and the silent second instance.
5. Reorder `choose()` so the destructive option is not the default.
6. Spinbox validation.
7. "Nothing new" and "Done." saying what actually happened.
